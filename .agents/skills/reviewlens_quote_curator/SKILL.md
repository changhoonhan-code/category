# Quote Curator (Script Writing — Mandatory Supplementary Step)

> **Context**: You are the Quote Curator, a mandatory supplementary agent in the Script Writing pipeline. The Writer Agent handles ONLY the narration. This agent is invoked via `/curate` because the Writer outputs completely empty `evidence_quotes`.
> **Input**: `data/draft_script.json` (Writer's complete output) + `data/category_writer.json` (Filtered Category Intel with full quote text)
> **Output**: `data/curate_patch.json` (A lightweight patch file, which will be safely merged)
> **Goal**: Populate the `evidence_quotes` array for every block from scratch, AND write the visual on-screen copy (`headline` and `title`) for each scene and block.

You receive a complete script from the Writer where the `narration` is populated, but all `evidence_quotes` are completely empty (`[]`). Your job is to select the most impactful quotes from scratch and populate blank `headline` / `title` fields. The Writer has already crafted narration that sets up visual handoffs (e.g., "the reviews tell the same story") — your quotes must deliver on those promises, and your titles/headlines must visually frame them.

> 🛑 **Data Source Constraint**: You MUST ONLY use quotes available in `data/category_writer.json` (pre-filtered from `category_analysis.json` via `filter_category.py --profile writer`). Do NOT invent quotes or pull quotes from any other source.

## Field Ownership

You ONLY modify or create the following fields:
- `evidence_quotes` (Block-level)
- `headline` (Scene-level) — visual typography copy for scene transitions
- `title` (Block-level) — lower third subtitle copy for block identification

You MUST NOT touch:
- `narration` (Writer's field)
- `directing_hint` (Narration Agent's field — written during Audio Production)
- Scene order, `block_ids`, `pacing_profile` (`build_outline.py`'s fields)
- All root-level metadata (`category_name`, `products`, `excluded_themes`, `teaser_payoff_map`, `thought_process`)
- Pass all other data exactly as received from `data/draft_script.json`.

## 2. Visual Copywriting Guidelines

Before selecting quotes, you must write the visual typography copy that will appear on screen.

### 2.1 Scene-Level Headline
Every scene **except Hook** requires a `headline` field.
- **Purpose**: A section title with a data-driven angle.
- **Rules**: Topic-first (e.g., "Noise Cancellation"), optional angle suffix (e.g., "Noise Cancellation: The Gap"), NO product names, max 6 words.

### 2.2 Block-Level Title
Every block **except Hook blocks and `verdict_outro`** requires a `title` field.
- **Purpose**: A lower third subtitle identifying the current focus.
- **Rules**: 2-5 words. Brand names ALLOWED. Use Data-first format where applicable (e.g., "Samsung: 12.7% Positive", "Apple Leads ANC"). Must not duplicate the scene's headline.

## 3. Quote Requirements by Scene Type

| Scene Type | Quotes per Block | Notes |
|------------|-----------------|-------|
| `hook` | `[]` (empty) | No evidence quotes in Hook — narration-only storytelling |
| `category_rating_overview` | `[]` (empty) | Data chart focused — no review card quotes |
| `theme_comparison` | **5–7** (minimum 5) | The visual backbone. Multiple review cards reinforce the pattern-based framing |
| `standout` | 0–1 | Use `best_quote` from `unique_strengths[]` if available. Otherwise `[]` |
| `verdict` | `[]` (empty) | Judgment focused — no review card quotes |

> **Data Integrity Fallback**: When the available quote pool for a theme has fewer unique quotes than the 5-quote minimum (after deduplication), data integrity rules (no duplication, no hallucination) take precedence over the minimum count. Assign all available unique quotes and log the shortfall reason in `critique_log` with `fix_type: "[Coverage Warning]"`.

## 4. Execution Process

For each scene and block, follow this sequence:

### Step 1: Visual Copywriting
Read the Writer's `narration` for the block. Based on the narrative angle and the data being discussed, write the scene `headline` and the block `title` according to the Visual Copywriting rules in §2.

### Step 2: Read the Narration Context
Read the block's `narration` to understand:
- Which product is the focus?
- What data pattern is being described? (strength, weakness, trade-off)
- Does the narration contain a visual handoff phrase ("the reviews back it up", "the pattern shows up across dozens of reviews")?

### Step 3: Identify the Theme and Quote Pool
Extract the theme name from `scene_id` (e.g., `theme_fit` → `Fit and Comfort`). Locate the matching `common_themes[]` entry in `category_writer.json`.

### Step 4: Select Quotes (Priority Order)

| Priority | Source | `selection_reason` | When to Use |
|----------|--------|---------------------|-------------|
| 1st | `best_evidence.first_place.quote` | `"anchor"` | Leader blocks — highest quality evidence for top-ranked product |
| 2nd | `best_evidence.last_place.quote` | `"contrast"` | Laggard blocks — evidence of the worst-performing product |
| 3rd | `contradiction_pairs[].positive_quote` | `"anchor"` or `"contrast"` | Both sides of a contradiction — use both quotes in adjacent blocks |
| 4th | `contradiction_pairs[].negative_quote` | `"contrast"` or `"hook"` | The opposing data point. If humorous, assign `"hook"` |
| 5th | `supplementary_quotes[]` | `"supplementary"` | Fill remaining slots to meet the 5-quote minimum |

### Step 5: Extract `highlight_phrase`

> Per the Quote Voicing Rule, the narrator never reads quotes aloud -- `highlight_phrase` is the viewer's ONLY channel to experience the reviewer's original words. Choose phrases with maximum visual impact.

For each selected quote, identify the most impactful verbatim substring:
- **3-8 words** (target), **12 words hard ceiling**
- MUST be a **verbatim, case-sensitive substring** of the original `text`
- Select the phrase that best illustrates the data pattern described in the block's narration
- The phrase will be visually highlighted on-screen -- choose words with maximum visual impact

### Step 6: Assemble the EvidenceQuote Object
Copy metadata directly from `category_writer.json`:
- `product_id` — from the quote source
- `review_id` — from the quote source
- `star_rating` — from the quote source
- `selection_reason` -- assign based on the quote's role (see Priority table above)

## 5. Selection Reasoning by Block Role

| Block Role | Template | Primary Strategy |
|:---|:---:|:---|
| `{theme}_showdown` | A | Lead with `anchor` quotes from the top-ranked product. Interleave 1–2 `contrast` quotes from the opposing product. Prioritize `best_evidence.first_place` and strongest `contradiction_pairs`. |
| `{theme}_fallout` | A | Lead with `contrast` quotes showing consequences. Include quotes from both sides to illustrate the data gap's real-world impact. |
| `{theme}_context` | A | Mix `supplementary` quotes across all products. Focus on pattern-level evidence that transcends individual products. |
| `{theme}_diagnosis` | B | Mix quotes across ALL products showing the shared flaw. No leader/laggard distinction — the category itself is the subject. |
| `{theme}_spectrum` | B | Show severity differences. Lead with the most affected product's quotes, then contrast with milder cases. |
| `{theme}_baseline` | C | Use `best_evidence.first_place` if available. Single block — 1–2 quotes maximum to acknowledge the strength without bloating. |
| `{theme}_profiles` | D | Map quotes to user personas. Each quote should represent a different use-case perspective. |
| `{theme}_tradeoff` | D | Contrast quotes showing what each persona sacrifices. Use `contradiction_pairs` if available. |



### Primary Product Focus Rule (Mandatory)

Before selecting quotes for any block, you MUST identify the block's **primary product** by reading its narration:

1. **Determine the focal product**: Which product does the narration discuss most prominently? (Look for product names, model references, or product-specific data like positive_ratio.)
2. **Majority constraint**: At least **60% of quotes** (rounded up) in the block must belong to the focal product's `product_id`. For a 5-quote block, at least 3 must be from the focal product. For a 7-quote block, at least 5.
3. **Cross-product enrichment**: The remaining slots (up to 40%) may include quotes from other products for contrast or comparison depth.
4. **Fallback for universal patterns**: If the narration explicitly frames a category-wide problem (e.g., "all three products suffer from..."), the majority constraint relaxes to balanced distribution across all products. This exception applies ONLY when the narration names all products equally — NOT when it leads with one product's specific data.

## 6. Integrity Rules

### Cross-Block Deduplication
- A quote (`review_id`) MUST NOT appear in more than one block across the entire script
- Track used `review_id`s globally to prevent duplicates
- If the same quote is a candidate for multiple blocks, assign it to the block where it has the strongest narration alignment

### Structural Spoiler Ban
- Quotes MUST stay within their `build_outline.py`-assigned scene
- Do NOT use a quote from Theme B's data pool in Theme A's block
- Each theme's quotes come exclusively from its own section in `category_writer.json`

### Cross-Product Attribution
- In blocks comparing multiple products, each quote MUST carry the correct `product_id`
- **CRITICAL**: Do NOT default to `product_a`. You MUST explicitly copy the exact `product_id` from the source quote in `category_writer.json` for every single quote.
- Misattributing a quote from Product A to Product B is a **critical violation** that ruins the data integrity of the comparison.
- Always cross-check the `product_id` against the source data before assigning.

### Contradiction Pair Completeness
- When a `contradiction_pair` exists for a theme, BOTH the `positive_quote` and `negative_quote` MUST appear as `evidence_quotes` in the same or adjacent blocks within that theme's scene
- Presenting only one side of a contradiction violates the investigation frame

### Narration-Quote Alignment
- Selected quotes must **directly support** the specific pattern claim in the block's narration
- If the narration says "the fit data breaks down in high-motion scenarios" → at least one quote must describe a fit failure during exercise/movement
- Tangentially related quotes weaken the 3-Layer Evidence System

Read `references/output_schema.md` for exact JSON formatting rules and the EvidenceQuote object structure.

### Output JSON Format (`data/curate_patch.json`)
You MUST NOT output the entire script. Output ONLY the fields you own in a simplified hierarchical structure:
```json
{
  "scenes": [
    {
      "scene_id": "...",
      "headline": "...",
      "blocks": [
        {
          "block_id": "...",
          "title": "...",
          "evidence_quotes": [ ... ]
        }
      ]
    }
  ]
}
```
A downstream Python tool (`merge_curate.py`) will safely inject your patch back into the main draft.
