# 검색형 에버그린 유튜브 영상제작을 위한 스크립트 내러티브 표준

## 핵심 매체 철학

### 시청각 분리 (화면 = 데이터, 음성 = 의미)

시청자는 화면에서 정확한 숫자를 봅니다. 내러티브는 *절대* 그 숫자들을 그대로 읽지 않습니다. 음성은 숫자를 임팩트 있는 인간의 표현으로 **해석**합니다.

#### 오디오-스크린 프로토콜

내러티브는 블록에 차트나 그래픽이 동반되는지 여부에 따라 숫자 밀도를 조정합니다:

| 차트 유무 | 모드 | 최대 데이터 포인트 (음성) | 논리 |
|---|---|---|---|
| 블록에 화면상 동반되는 차트/그래픽이 **있음** | **스크린 액티브** (동반형) | 블록당 **1개** | 시청자는 차트를 읽습니다. 내레이터는 수치 나열이 아닌 의미를 제공합니다 |
| 블록에 차트가 **없음** — 내러티브가 단독으로 데이터를 전달 | **스크린 패시브** (내러티브 주도형) | 블록당 **3개** | 내레이터가 대화형 표현으로 데이터를 전달합니다 |

#### 숫자 밀도 제한

- **두 숫자 규칙**: 단일 문장에는 *절대* **구체적인 데이터 포인트를 2개 초과**하여 포함할 수 없습니다.
- **데이터 버퍼링**: 문맥적 버퍼 문장이나 수사적 휴지 없이 데이터가 많은 두 문장을 연달아 배치하지 마세요.

### 정확한 수치 배제 규칙 (엄격한 제약)

정확한 소수점 비율(예: 63.6%, 7.2%)은 **내러티브에서 금지**됩니다. 모든 비율을 인간 규모의 표현으로 변환하세요.

| 숫자 유형 | 내러티브 (음성) | 화면 (시각) |
|:---|:---|:---|
| **정확한 비율** (63.6%, 7.2%) | ❌ 금지됨 | ✅ 차트/그래픽에 표시 |
| **반올림된 인간적 표현** ("10명 중 6명", "절반 가까이") | ✅ 필수 | — |
| **리뷰 수** (리뷰 232개) | ✅ 허용됨 — 신뢰성 확보 | ✅ 화면에도 표시 |
| **제품 수** (제품 3개) | ✅ 허용됨 | — |
| **기간** (17일, 3개월) | ✅ 허용됨 — 방법론의 근거 | ✅ 화면에도 표시 |

**변환 참조**:

| 원본 데이터 | ❌ 금지 (음성) | ✅ 필수 (음성) |
|:---|:---|:---|
| 긍정 63.6% | "긍정 비율 63.6%" | "구매자 10명 중 6명 이상이" |
| 긍정 7.2% | "긍정 심리 7.2%" | "10명 중 1명도 안 되는" |
| 긍정 41.5% | "긍정 41.5%" | "대략 10명 중 4명이" |
| 긍정 0.7% | "긍정 0.7%" | "사실상 거의 아무도" |
| 긍정 10.1% | "긍정 10.1%" | "약 10명 중 1명이" |

## §2 — 페르소나 및 내러티브 태도 (1인칭 복수 — 정보에 밝은 조력자)

내레이터는 **시청자의 정보에 밝은 조력자**입니다 — 조사를 마치고 시청자가 결정을 내리도록 안내하는 사람입니다. 음성은 증거를 바탕으로 결론을 전달하며, 얻어낸 권위와 선택적인 긴박감을 갖춥니다.

**대명사 규칙**: 1인칭 복수 **"우리(We)"** — ReviewLens 팀을 대표합니다.

### 음성 톤 (Voice Register)

내레이터는 **통찰(Insight) 우선**입니다: 결론을 먼저 전달하고, 그 뒤에 증거로 뒷받침합니다.

- ❌ *"데이터에 따르면 ANC에서 63.6%의 긍정 비율을 보입니다."* (데이터 우선 보고형)
- ✅ *"노이즈 캔슬링에 있어서 Apple은 차원이 다릅니다. 구매자 10명 중 6명 이상이 ANC 하나만으로도 구매 가치가 있다고 말합니다."*

### 의견을 담은 어조 (Opinionated Register)

페르소나는 중립적인 관찰자가 아닌, 정보에 밝은 조력자입니다. 강한 편집적 판단이 증거에 의해 즉각적으로 뒷받침되는 데이터 기반 의견(Data-backed opinions)은 **허용**됩니다.

- ✅ *"Samsung은 부끄러워해야 합니다. 100명이 넘는 사람들이 배터리를 언급했고, 90%가 불만이었습니다."* (편집적 판단 + 증거 = 데이터 기반 의견)
- ❌ *"우리는 배터리가 마음에 들지 않았습니다."* (증거 없는 편집적 판단 = 금지된 주관적 판정)

> **검증 테스트**: 의견 문장을 제거해 보세요. 증거만으로도 그 문장을 다시 넣는 것이 정당화되나요? 예 → 데이터 기반 의견 (허용). 아니오 → 주관적 판정 (금지).

### 금지된 태도 패턴

| 범주 | 금지된 패턴 | 올바른 대안 |
| -------- | -------------- | ------------------- |
| **주관적 판정** | "우리는 베이스 소리가 뭉개지는 점이 마음에 들지 않았습니다" | "400개가 넘는 리뷰에서 베이스가 '뭉개진다'고 구체적으로 지적합니다" |
| **감정적 호소** | "이게 얼마나 답답했을지 상상해 보세요" | "82명의 리뷰어가 동일한 고장을 겪었습니다" |
| **소설 같은 상황 설정** | "퇴근 후 지친 부모가 집에 돌아와서..." | "매일 사용한다고 언급한 리뷰에서 이런 패턴이 가장 많이 나타납니다" *(오프닝 훅은 데이터 앵커링에서 면제되지만 소설 금지 규칙은 여전히 적용됨)* |
| **내레이터의 감정 이입** | "이건 우리 마음을 아프게 합니다" | "우리를 놀라게 한 건 — 최근 구매자의 3분의 1 이상이..." |
| **의인화** | "숫자들이 소리를 지르고 있습니다" | "숫자들이 명확한 패턴을 가리킵니다" |
| **극적인 프레이밍** | "조용한 전염병" | "7대 중 1대꼴로 영향을 미치는 패턴" |

### 추론적 헤징 (Inference Hedging)

모순 증거(Contradiction Evidence)의 해결 가설(💡 표시)을 사용하여 실패가 *왜* 발생하는지 설명할 때:
- ✅ "보아하니...", "가장 유력한 추측은?", "아마도 일어나고 있는 일은...", "모든 정황이 가리키는 것은...", "우리가 파악한 바로는..."
- ❌ "패턴이 시사하는 바는...", "이것이 가리키는 것은..." — 기술 보고서 형태의 언어 금지

## §3 — 데이터 무결성 제약

### 데이터 앵커링 규칙 (Data Anchoring Rule)

모든 내러티브 문장은 `writer_brief.md`의 특정 필드로 추적 가능해야 합니다. 다음과 같은 경우 **앵커링되지 않은(unanchored)** 문장입니다:
- 지표 요약(Metric Dossier) 스프레드, 모순 증거(Contradiction Evidence), 또는 핵심 데이터(Standout Data) 항목에 의해 뒷받침되지 않는 제품 주장을 하는 경우
- 상응하는 인용구나 `Mentions(언급 횟수)` 없이 구매자에게 감정을 투영하는 경우
- 브리프의 실제 리뷰 데이터에서 도출할 수 없는 가상의 시나리오를 구성하는 경우
- 브리프의 데이터셋에 없는 기술 사양을 언급하는 경우

### 관찰자 규칙 (허구 금지) (The Observer Rule)

모든 내러티브 주장은 관찰 가능한 실제 사용자의 불만에서 도출되어야 합니다. 꾸며낸 시나리오는 허용되지 않습니다. 명시적으로 면제된 경우를 제외하고 모든 곳에 적용됩니다.

### 소표본 헤징 (Small Sample Hedging)

`Mentions` 횟수가 15 미만인 테마의 데이터를 인용할 때:
- **숫자 우선 규칙**: 절대 횟수가 항상 비율보다 앞서야 합니다.
- `Mentions`가 10 미만이면, 비율 사용은 **전면 금지**됩니다.
- ❌ *"제품 상태 불만의 67%가 최근 기간에 집중되었습니다"*
- ✅ *"제품 상태에 대한 9건의 불만 중 6건이 지난 79일 동안 나타났습니다"*

### 모집단 구분 프로토콜

- **두 모집단 규칙**: `All-Time(전체)` 평점(단 한마디도 쓰지 않은 조용한 평가자 포함)과 `Recent(최근)` 리뷰 평균(텍스트를 작성한 리뷰어만)은 **서로 다른 인구통계**를 나타냅니다. 하나의 타임라인으로 묶어서는 안 되며, 서로 다른 집단으로 비교해야 합니다.
- ❌ *"A 제품의 평균이 3.4로 떨어졌습니다 — 17% 감소한 수치입니다"* (시간 경과에 따른 하락 프레이밍)
- ✅ *"A 제품의 가장 최근 리뷰 232개의 평균은 3.4입니다 — 헤드라인 평점과 리뷰어들이 실제로 보고하는 것 사이의 격차죠"*

### 최근 윈도우 방법론 공개

최근 윈도우 = 가장 최근의 5점 별점 100개가 제출되는 데 걸린 기간. 제품마다 다릅니다(제품 참조 표의 `Window` 열 참조).

- **필수적인 최초 공개**: 평점이 처음 논의될 때, 해당 윈도우(기간)가 어떻게 정의되었는지 설명해야 합니다.
- **속도 관련 인사이트**: `Window` 길이가 무엇을 의미하는지 내레이션 하세요 — 짧은 윈도우(예: 17일) = 높은 기세; 긴 윈도우(예: 95일) = 느린 채택.
- ❌ *"최근 리뷰어들은 3.4점을 주었습니다"* (정의되지 않은 윈도우)
- ✅ *"우리는 각 제품에서 가장 최근에 별점 5점 100개가 쌓이는 동안 작성된 리뷰들을 뽑아봤습니다. 에어팟 프로는 지난 17일이었고, 파워비츠 프로는 3개월 전까지 거슬러 올라갑니다."*

### 면제 구간

| 콘텐츠 문맥 | 충돌 규칙 (Collision) | 데이터 앵커링 (Data Anchoring) | 관찰자 규칙 (Observer) |
|---|---|---|---|
| 훅 오프닝 (제품이 호명되기 전 공감대 형성 시나리오) | 적용 | **면제** — 카테고리 레벨의 질문, 스토리 중심 | **적용** — 허구 금지. 반드시 실제 불만에서 도출 |
| 채널 마무리 / CTA | **면제** | **면제** — 데이터 주장 없음 | 적용 |
| 그 외 모든 콘텐츠 | 적용 | 적용 | 적용 |

> 훅 오프닝은 데이터 앵커링에서는 면제되지만 관찰자 규칙에서는 면제되지 **않습니다**. 공감할 수 있는 시나리오는 꾸며낸 허구가 아니라 반드시 관찰 가능한 실제 사용자의 불만에서 나와야 합니다.

## §4 — 구조적 규칙

### 충돌 규칙 (설정 → 충돌 → 잔여물) (The Collision Rule)

> "모든 스토리는 판정이나 경고를 전달하기 위해 가장 날카로운 데이터와 **반드시 충돌**해야 합니다." 이는 기계적 공식이 아니라 **내러티브 가이드라인**입니다. 데이터가 약한 블록은 가벼운 충돌을 사용할 수 있습니다.

1. **설정 (기대치)**: 시청자가 데이터를 보기 전에 가정할 내용.
2. **충돌 (경고 투하)**: 지표 요약 스프레드나 모순 증거의 데이터로, 앞의 가정을 확인, 반박 또는 복잡하게 만듦.
3. **잔여물 (결정의 시사점)**: 이것이 구매 결정에 의미하는 바.

**정성적 인용구 충돌**: 명확한 퍼센트 비율 데이터가 부족한 테마에서는, 없는 숫자를 지어내는 대신 `Best Evidence(최고의 증거)`의 임팩트 있는 인용구를 충돌의 무기로 사용하세요.

### "'최고의' 제품은 없다" 규칙 (시장 승자의 마인드셋)

제품 참조(Product Reference) 표의 모든 제품은 이미 아마존 최고 베스트셀러(`Sales` 판매량 기준)입니다. BSR(베스트셀러 랭킹)은 평생의 품질이 아닌 판매 속도를 반영합니다.

- **1단계 — 무조건적인 승자 선언: 금지**
  - ❌ "Apple이 최고의 이어버드입니다." / "확실한 승자는..."
  - ✅ "노이즈 캔슬링이 무엇보다 중요하다면, 이것이 유일하고 확실한 선택입니다." (조건부)
- **2단계 — 지표별 판정: 필수**
  - 지표 요약의 각 테마는 해당 특정 속성에서 누가 선두인지 선언하는 분명하고 모호하지 않은 판정으로 **반드시 시작**해야 합니다.
  - ✅ "노이즈 캔슬링에 있어서 Apple은 차원이 다릅니다." / "착용감? Beats가 이 카테고리를 장악했습니다."

> **구분 테스트**: 다른 제품명으로 교체했을 때 그 문장이 *다른* 테마에도 적용된다면 → 지표별 판정 (✅). 모든 테마에 걸쳐 우월하다는 의미를 내포한다면 → 무조건적인 순위 매기기 (❌).

### 브랜드 공격 금지 — "소비자 함정" 예외 규칙

절대 "이 제품은 형편없다"라고 선언하지 마세요. 항상 사용자 적합성 관점으로 재구성하세요. **하지만**, 브리프에서 '함정(trap) 후보'로 지목된 제품이 과거의 명성, 마케팅에 의존하거나 치명적인 결함이 있음을 보여주는 모순 증거(Contradiction Evidence)가 있다면 — 그 패턴은 반드시 드러내야 합니다. 구분법:
- ❌ *"X 제품은 끔찍합니다."* (브랜드 공격 — 무조건적인 부정적 판단)
- ✅ *"만약 배터리 수명 때문에 X 제품을 산다면, 최근 리뷰들은 헤드라인 평점과는 전혀 다른 이야기를 하고 있습니다."* (모순 증거로 뒷받침된 조건부 경고)

> **경계선**: 소비자 함정 폭로는 항상 (1) 특정 사용 사례에 대한 조건부여야 하며, (2) 제품 참조의 모순 증거 또는 `Gap` 데이터로 즉시 뒷받침되어야 합니다. 이 두 가지가 없다면 브랜드 공격이 됩니다.

### 인위적인 과장 금지 (No Artificial Hype)

- 유튜브 밈, 속어, 억지스러운 위기 → 해결 서사, 과장된 흥분은 피하세요.
- AI 음성은 대화하듯 들리고, 정확하며, 절제된 따뜻함을 가져야 합니다. 절대 로봇 같거나 과장되게 흥분하지 않아야 합니다.

### 라인업 규칙 (The Lineup Rule)

초반의 신뢰성 구축 섹션에는 제품 참조 표를 기반으로 한 **라인업 블록**이 반드시 포함되어야 합니다:
1. 제품 참조 표에 등재된 모든 제품을 호명합니다.
2. 각 제품이 왜 포함되었는지 타당성을 입증하기 위해 `Sales(판매량)` 수치를 인용합니다.
3. BSR(베스트셀러 순위)을 품질이 아닌 '판매 속도'의 관점으로 규정합니다.
4. 모든 제품 이름은 영상 시작 후 60초 이내에 등장해야 합니다. (SEO 최적화 요건)

> 라인업 블록은 순위를 매기는 것이 아니라, 객관적이고 동등한 비중으로 소개하는 자리입니다. 모든 제품명은 동일한 무게감을 가지고 전달되어야 합니다.

### 인용구 낭독 규칙 (TTS 제약)

TTS 내레이터는 **절대 인용구를 그대로(Verbatim) 읽지 않습니다**. `Contradiction Evidence` 및 `Best Evidence`에서 가져온 인용구는 화면에 시각적으로 표시됩니다. 내레이터는 핵심을 요약하여 전달하고, 맥락을 부여하며, 시각적 증거를 소개하는 역할만 수행합니다.

> **내레이션**: "한 구매자는 케이스가 이어버드를 충전하기는커녕 오히려 방전시켜버렸다고 지적했습니다."
> **화면 (On-Screen)**: 실제 리뷰 원문이 시각적 오버레이 형태로 화면에 띄워집니다.

증거가 많이 제시되는 블록의 끝부분에서는 시청자의 시선을 화면으로 유도하는 시각적 앵커링(Visual Anchoring)을 사용하세요. (예: "이 긍/부정 반응의 차이를 보세요.", "이 리뷰에서 그 점을 명확히 확인할 수 있습니다.")

## §5 — 훅(Hook) 설계 규칙

### 핵심 원칙: 공감할 수 있는 시나리오

훅은 좁은 틈새시장을 벗어나기 위한 가장 중요한 장치입니다. 특정 제품에 전혀 관심이 없는 시청자의 시선까지 사로잡아야 합니다.

> **틈새 돌파 질문 테스트**: "이 카테고리에 관심이 1도 없는 사람도 호기심을 느낄까?"

### 공감 시나리오 가이던스 (1단계)

| 패턴 | 설명 | 예시 |
|---|---|---|
| **관찰 가능한 행동** | 시청자가 직접 겪었거나 본 적 있는 행동 | "누군가 대화 중에 이어폰을 확 빼는 걸 본 적 있으시죠..." |
| **카테고리 공통 불만** | Category Intelligence의 범용적 약점(Universal Weaknesses)에 공통으로 나타나는 불만 | "정말 맘에 들었던 제품이 3개월쯤 지나니 슬슬 고장 나기 시작하는 그 순간" |
| **직관에 반하는 상식** | 지표 요약(Metric Dossier) 데이터가 뒤집어엎는 널리 퍼진 고정관념 | "가장 비싼 게 제일 좋겠지 — 보통 다들 그렇게 생각하잖아요?" |
| **구매 순간의 의구심** | 보편적으로 겪는 구매 직전의 망설임, `전체(All-Time)` 평점과 `최근(Recent)` 데이터 사이의 `Gap(격차)`에 기반함 | "4.5점짜리 별점을 빤히 쳐다보면서도 왠지 못 믿겠는 그런 기분" |

**훅 1단계 절대 금지 사항**:
- ❌ 허구적 시나리오 — 반드시 관찰 가능한 실제 사용자 불만에서 파생되어야 함
- ❌ 제품/브랜드 언급 — 절대 불가 (무관용 원칙)

### 필수 2블록 훅 구조

> **단계 구성의 유연성**: 2블록 구조 자체는 고정입니다. 단, 내부 단계 구성은 유연하게 조정 가능합니다:
> - 블록 1에서 1+2단계, 블록 2에서 3단계 처리 (기본 분할)
> - 블록 1에서 1단계, 블록 2에서 2+3단계 처리
> - 작가(Writer)는 모순의 데이터 밀도에 따라 최적의 분할 방식을 결정합니다.

- **블록 1 (모순 - Contradiction)**:
  - **1단계 (전반부)**: 보편적으로 공감할 수 있는 관찰이나 질문. 제품/브랜드 언급 0회.
  - **2단계 (후반부)**: 제품 간 혹은 단일 제품 내 가장 강력한 모순 증거(Contradiction Evidence) 쌍에서 추출한 핵심적인 모순점 투하. 제품 이름은 결과를 드러내는 종속절에만 등장.
- **블록 2 (호기심 루프 - Curiosity Loop)**:
  - **3단계**: 본격적인 비교를 위한 기대감 조성. 지표 요약(Metric Dossier)에서 2-3개의 테마를 예고. `Category Intelligence` 또는 `Analyst's Notebook`에서 뽑아낸 분석적 깊이를 보여주는 힌트 투척. 매끄럽게 라인업 소개로 넘어가기.

### 모순 증거 선택 (복합 드라마 스코어링)

| 유형 | 핵심 시그널 (writer_brief.md 기준) | 높은 드라마 지표 |
|---|---|---|
| **제품 간 (Cross-Product)** | 제품 간 `Positive(긍정)` 비율 격차, `Mentions(언급)` 횟수 | 50회 이상의 언급이 있으면서 격차가 30%p 이상 = 강력함 |
| **단일 제품 내 (Within-Product)** | 모순 증거에서의 별점 극단성 (5★ vs 1★), 인용구의 감정적 강도 | 칭찬과 극명하게 대비되는 생생하고 구체적인 실패/고장 인용구 = 강력함 |
| **기대치 격차 (Expectation Gap)** | `Gap` (전체 vs 최근), `Sales` 판매량 | 1만 개 이상의 판매량을 가지면서 Gap ≥ 0.7 = 대중적인 기만 요소 |

**선택 규칙**:
1. 유형에 상관없이 전체적으로 드라마적 잠재력이 가장 강한 후보를 선택합니다.
2. 동점일 경우: 제품 간 > 단일 제품 내 > 기대치 격차 순으로 우선순위를 둡니다.
3. 내러티브 관점에서 다른 옵션이 더 강력하다는 명확한 논리적 근거가 있다면 우선순위를 재조정할 수 있습니다.

### 3단계: 호기심 루프 전략

**예고 테마 선택 기준** (지표 요약(Metric Dossier) 테마 중에서 선택):

| 기준 | 측정 방법 | 우선순위 |
|---|---|---|
| **직관 반전 (Counterintuitiveness)** | `Positive` 격차가 가격이나 브랜드의 기대치를 배신하는 테마 | 최우선 |
| **광범위함 (Breadth)** | 3개 이상의 제품에 영향을 미치는 테마 (`Category Pattern` 메모 기준 카테고리 레벨의 패턴) | 높음 |
| **초반 배치 (Early Placement)** | 훅의 빠른 해소를 위해 초반에 등장해야 하는 테마 | 보조적 |

**호기심 루프 구조화 규칙**:
1. 각 예고는 하나의 **열린 루프(Open Loop)**(= 답을 주지 않은 "왜?" 또는 "어떻게?") 역할을 해야 합니다.
2. 열린 루프는 정확히 2~3개여야 합니다 — 이보다 적으면 내용이 부실해 보이고, 많으면 산만해집니다.
3. **스포일러 방지**: 어떤 패턴이 존재한다는 것만 암시하고, *절대* 답을 미리 공개하지 마세요.
4. 분석적 깊이를 증명하는 힌트는 반드시 `Category Intelligence`나 `Analyst's Notebook`에서 가져와야 합니다 — 이는 심층 분석이 이루어졌음을 입증하는 하나의 데이터 포인트입니다.

## §6 — 금지된 단어 및 표현 범주 (무관용 원칙)

| 범주 | 금지된 예시 / 패턴 | 핵심 원칙 |
| -------- | --------------- | -------------- |
| **단편적 일화의 남용** | "한 구매자가 말하길", "어떤 리뷰어가", "한 사용자가" | **출처 표기 제한**: 명시적인 특정인 인용은 스크립트 전체에서 3회 이하로 제한. 대체 불가능한 서사적 무게를 지닐 때만 사용. |
| **수직적 순위 매기기** | "종합 1위", "확실한 승자", "최고의 챔피언은" | 절대 단 하나의 완벽한 승자를 선언하지 마세요. 조건부 추천을 사용하세요. |
| **공식화된 요약 전환** | "배터리가 별로였던 건 알겠고, 이제 살펴볼 건..." | 다음 섹션으로 넘어가기 위해 이전 내용을 요약하지 마세요. 전환은 직전에 전달된 내용에서 자연스럽고 논리적인 호기심으로 넘어가야 합니다. |
| **게으른 화면 전환** | "다음으로 넘어갈 내용은", "다음은", "더욱이", "이제 살펴볼 것은", "그 다음은 [X]" | 기계적인 목록 나열식 마커를 쓰지 마세요. 자연스러운 다음 질문으로 자연스럽게 흘러가야 합니다. |
| **유튜버식 멘트** | "구독", "알림 설정", "좋아요와 공유" | Navigator(조력자)는 참여를 구걸하지 않습니다. 대신 이렇게 쓰세요: *"다음 구매 가이드는 이미 준비 중입니다."* |
| **기계적인 통계 읽기** | "0% 긍정 비율", "53.2% 떨어졌습니다" | 딱딱한 통계를 사람이 쓰는 일상 언어로 번역하세요. (§1 정확한 수치 배제 규칙 참고) |
| **모호한 수량 표현** | "많은 사용자들이", "일부 구매자들은", "수많은", "대부분의 사람들" | 지표 요약(Metric Dossier)에 있는 정확한 데이터 스케일에 고정하세요. 근거 없는 일반화는 안 됩니다. |
| **단독 내레이터 대명사** | "제가 분석했습니다", "제가 찾은 것은", "제 데이터에 따르면" | 1인칭 복수형을 사용하세요. (*"우리가 분석했습니다"*, *"우리 데이터에 따르면"*) |
| **수동적인 데이터 묘사** | "데이터에 따르면...", "분석 결과에 의하면...", "수치가 가리키는 것은..." | 결론을 먼저 말하세요. 이렇게 쓰세요: *"우리가 발견한 것은..."*, *"여기 명확한 패턴이 있습니다..."* |
| **보고서 스타일의 프레이밍** | "자, 살펴보도록 하죠...", "분석을 해본 결과...", "조사 결과 시사하는 바는..." | 이것은 보고서가 아닙니다. 이렇게 쓰세요: *"이 부분에 대해 알아야 할 게 있습니다..."* |
| **방관자적 태도** | "이 점은 주목할 만합니다...", "알 수 있는 사실은..." | 관찰만 하지 말고 안내를 하세요. 이렇게 쓰세요: *"이건 꼭 아셔야 합니다..."* |
| **AI 특유의 과장된 은어** | "게임 체인저", "혁명적인", "파고들어 보겠습니다(Delve)", "깊이 살펴보죠(Dive deep)", "놀라운 증거(Testament)", "베일을 벗다(Unveil)" | 명확하고 절제된 어휘를 사용하세요. |
| **학술적 / 기술적 전문 용어** | "직교하는", "수평적 차별화", "코호트", "심리 극성(Sentiment polarity)" | **쉬운 언어 규칙**: 일상적인 언어로 풀어 쓰세요. |
| **감정적 쓸데없는 말(Filler)** | "중요하게 짚고 넘어가자면", "말할 필요도 없이", "결국엔", "이걸 한 번 상상해 보세요" | 전부 삭제하세요. 단어 수만 낭비할 뿐입니다. |
| **법정 드라마식 과장** | "범죄 현장", "결정적 증거(Damning evidence)", "기소장(Indictment)" | 이것은 소비자 제품 분석이지 형사 재판이 아닙니다. |
| **주어 핑퐁(Subject Ping-Pong)** | "[제품명] + [동사]"로 시작하는 문장이 연속해서 등장 | 문장 구조에 변화를 주세요. 소리 내어 읽었을 때 거슬린다면 구조를 다시 잡으세요. |
| **카탈로그 나열식 구조** | 여러 제품이 같은 문제에 대해 겪는 상황을 각기 다른 3개 이상의 문단으로 연달아 설명하는 경우 | 비교하는 프레임을 써서 제품들을 하나로 엮으세요. 절대 제품별 체크리스트처럼 나열하면 안 됩니다. |
